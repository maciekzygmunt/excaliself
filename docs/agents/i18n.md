# UI text and translations

The app uses [Paraglide JS](https://paraglidejs.com). Messages live in `messages/<locale>.json`; the code calls them as typed functions from `@/paraglide/messages`. `src/paraglide` is generated and not in Git (`pnpm typecheck` and the Vite plugin create it).

## Rules

- Write every new message in all six files: `en`, `fr-FR`, `de-DE`, `es-ES`, `pl-PL`, `zh-CN`. Write natural UI text for each language, not a word-for-word copy of the English.
- Run `pnpm i18n:check`. It fails on a missing translation, variable or plural form.
- Group keys by area: `settings_members_invite_button`, not `invite_button`.
- Call `m.*()` at render time. A module-level `const LABEL = m.x()` runs once on the server, outside a request, so it is always English. Store the function (`label: m.x`) and call it later. For zod, use `{ error: () => m.x() }`.
- Do not build sentences from fragments. Give the translator the whole sentence with variables.
- Rich text: put markup in the message (`"You sign in as {#em}{email}{/em}."`) and render it with `<ParaglideMessage>` from `@inlang/paraglide-js-react`.
- Dates, numbers, lists and relative times: use `Intl.*` with `getLocale()` (see `formatAgo` in `src/lib/relative-time.ts`).
- The WebSocket routes run outside the request middleware: there `getLocale()` is always `en`. Pass `{ locale }` to `m.*()` explicitly.

## Plurals

English has `one` and `other`. Polish has `one`, `few` and `many` (and `other` for fractions). `*` is the `other` form. Example from `messages/pl-PL.json`:

```json
"settings_members_count": [
  {
    "declarations": ["input count", "local countPlural = count: plural"],
    "selectors": ["countPlural"],
    "match": {
      "countPlural=one": "{count} osoba",
      "countPlural=few": "{count} osoby",
      "countPlural=many": "{count} osób",
      "countPlural=*": "{count} osoby"
    }
  }
]
```

French and Spanish also need `many`; Chinese needs only `*`. `pnpm i18n:check` lists the forms that a locale is missing.
